## T3 — cb-stats kolonları + component-links service/action ✅
### cb-stats kolon açıklamaları
Sayfaya "column guide ▾" paneli + her başlığa tooltip eklendi (cb_stats.html).
Kolonların anlamı:
- **Source**: period türetme yolu (tmr-nominal H'yi belirler; sub/serv'in kendi
  periodu yoktur). **Period**: satırın KENDİ periodu — yalnız timer'larda; sub/serv'de
  '—' doğrudur, eksik veri değildir. **N fires**: oturum toplam yürütme.
- **H_tmr**: satırın EXECUTOR'ının timer-hiperperiodu = EX istatistik penceresi.
  Executor'daki her satırda aynı — servis satırında period sanılmasının kaynağı (T2).
- **μ/σ/min/max_EX**: H_tmr penceresi başına yürütme sayısı; pencereler cb'nin ilk
  ve son yürütmesi arasında, aradaki sessiz pencereler 0 sayılır.
- **μ/σ/min/max_sess**: aynı istatistik, pencere = oturum-geneli timer LCM'i.
### min_sess=max_sess bilmecesi (Autoware) — kök neden
H_session = 3.33M s (co-prime periodların LCM patlaması) >> 408 s oturum → her
cb'ye TEK oturum penceresi → μ=min=max, σ=0 (yapısal). unet'te H küçük → çok
pencere → değerler farklı. Sayfaya kırmızı "⚠ H_session > duration → sess stats
have 1 window" uyarısı eklendi. Redundans: EX ve sess grupları yalnız
H_tmr=H_session iken (tek-executor oturumlar) özdeş — kolonlar KALDI, rehber
bunu açıklıyor (silmek Autoware tarzı çok-executor oturumlarında bilgi kaybettirirdi).

## T4 — yeni FISH graph modeli + drill-down + GPU graph linkleme ✅ (v1)
**Yeni route: `/explore?session_id=…`** (fish_viz_server.py, server-side dot→svg,
her tıklama YENİ SEKME — graphviz URL/target öznitelikleriyle):
- **view=root (L0)**: üst-seviye namespace'ler (node+EX sayılarıyla).
- **view=ns&key=/x**: o namespace'in ALT-namespace'leri + executor'ları
  (L0→L1 eşlemesi; EX kutusunda ⚡ = altında GPU-submit eden node var).
- **view=ex&ex=<id>&key=/x**: yalnız tıklanan executor'ın (ns ile sınırlı)
  node'ları; **GPU-submit eden node'lar kırmızı + ⚡GPU işaretli** (gantt_meta
  gpu_submitter_cbs → F → N eşlemesi). unet doğrulaması: 11 node'dan 9'u ⚡ (doğru).
- **view=node&node=<id>**: node → E'ler (etype renkleri; T1 sayesinde waitable'lar
  `waitable→pub:<topic>` adlı) → F'ler (⚡'lı). F tıklanınca →
- **view=cb&cb=<addr>**: callback'in GPU sayfası: (a) callback İÇİNDEN launch
  edilen kernel'lerin stream-graf'ı (stream başına kernel sayısı, GPU süresi,
  top-5 kernel adı), (b) callback içindeki CUDA API profili tablosu, (c) legacy
  typed-DAG artifact'leri (dag_out/*.svg) linkleri.
**Önemli modelleme bulgusu (cb görünümünden çıktı):** NITROS bench'lerinde
kernel'ler çoğunlukla rclcpp callback SPAN'lerinin DIŞINDAKİ GXF worker
thread'lerinden launch ediliyor — callback'ler "GPU submitter" (event/copy API
çağrıları) ama korele kernel'i içermeyebiliyor; sayfa bunu dürüstçe söylüyor
("no kernels correlate … NITROS launches from GXF worker threads"). Bu, GPU
attribution'ın GXF-thread → besleyen-callback zincirine ihtiyaç duyduğunun
kanıtı — gpu_dag PG portu backlog maddesiyle birleşiyor.
**GPU graph linkleme durumu:** eski skeleton/conditional/stream DAG'leri üreten
gpu_dag.py Mongo/Influx dönemi (PG'ye taşınmamış; PG'de hiçbir F'te gpu_dags
attr'ı yok). v1 linklemesi: (a) canlı per-callback stream görünümü PG'den,
(b) dag_out artifact'leri /dag-out/ route'uyla servis edilip cb sayfasından
linkleniyor (imza-anahtarlı oldukları için per-callback filtrelenemiyorlar —
sayfada not düşülü). TAM linkleme = gpu_dag PG portu (ayrı iş, backlog).
**v1'de bilinçli eksikler:** ns/root görünümlerinde kardeşler arası comm
kenarları çizilmiyor (sadece hiyerarşi; components view zaten comm'u veriyor),
CN seviyesi gösterilmiyor. İstenirse v2.
