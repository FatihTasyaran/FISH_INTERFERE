## Paths that bypass rmw
| path | status |
|---|---|
| intra-process (rclcpp IPM) | traced (fish_rclcpp_intra_publish; FIFO pairing) |
| serialized / loaned publish and take, take_sequence | traced (fishwait12/15/17) |
| GenericSubscription dispatch | traced (fishwait13) |
| tf2 buffer reads | traced (fishwait14) |
| cuda_blackboard | VALIDATED 2026-10-04 on the package's own example (session fish_20261003_232233: publisher timer → CudaBlackboardSubscriber callback, 31/31 instances paired, intra-process). No new tracepoint: the trigger is an ordinary ROS message on `<topic>/cuda/_cuda_image` (instance id), the payload stays in process memory. One defect fixed: the hidden-name rule of topic_class (`*/_*`) classified that topic as infra and the task extractor dropped the edge (the model had it) → DATA_TOPIC_GLOBS `*/cuda/_cuda_*`. In stock Autoware no node PUBLISHES a /cuda topic (the CUDA concatenate node is not in the sample sensor kit), so the subscribers (centerpoint, optional CUDA voxel filter / ground segmentation) fall back to PointCloud2 — also covered. |
| iceoryx shared memory under Cyclone | RUN 2026-10-04. (1) Full Autoware does not start on Cyclone + iceoryx: RouDi's compile-time publisher-port limit is hit (`POSH__RUNTIME_ROUDI_PUBLISHER_LIST_FULL`, 37 processes aborted; Autoware has ~1 250 publishers) — a deployment finding, not a tracing one. (2) Small pub/sub deployment with shared memory (fish_20261003_231920): arrivals are still traced — fish_dds_rhc_store fires in an iceoryx listener thread of the subscriber process (comm = process name) instead of recvMC/recvUC; takes and callbacks unchanged; δ p50 0.08–0.10 ms (UDP loopback: 0.10–0.17 ms, same 4-subscriber app). (3) GAP found and closed: the iceoryx-only write path (dds_write_impl_iox → deliver_data_via_iceoryx) bypassed fish_dds_write → fishwait20 adds the tracepoint there (built, two call sites verified; not yet run). |
| Agnocast | VALIDATED 2026-10-04 (session fish_20261004_124636, image fishwait23, kernel module agnocast 2.3.1 on the host): sample talker / listener in both flavours (rclcpp::Node + Agnocast publisher on the hybrid executor; component in agnocast_component_container; Agnocast-only nodes with no rclcpp executor). extract_fish_tasks builds a vertex per Agnocast subscription callback and Agnocast timer from callable_start/end and pairs publish → callable by (topic, entry id): 2 731 / 2 731 instance pairs, 4 edges, δ p50 0.08–0.10 ms, no callback without a trigger. Three things had to be fixed on the way: (1) the image's libagnocast.so had its tracepoints compiled out (stock Humble tracetools has LTTng disabled) → agnocastlib rebuilt against the overlay (fishwait23); (2) FISH's nsys launch prefix dropped the application's LD_PRELOAD (libagnocast_heaphook.so) and the container died → prefix rewritten (python/fish/launch_wrap.py); (3) fs.mqueue.msg_max=256 is required → runner knob FISH_PRE_CMD. Residual: Agnocast entities are vertices of the TASK extraction only, not of the stored FISH graph (model_improved_pg has no Agnocast node/entity/F yet); agnocast_take (polling take) not consumed; no kernel split for Agnocast callables (C = window length). |
| rclcpp::WaitSet manual dispatch | RUN 2026-10-04 (fish_20261003_231606, stock Humble examples wait_set_subscriber + static_wait_set_subscriber next to an executor subscriber). Both wait-set readers appear as ordinary vertices with all 239 instances paired: the examples call `subscription->handle_message()`, which runs AnySubscriptionCallback::dispatch and therefore emits callback_start/end without any executor. The explicit manual-dispatch path of the extractor (a take that no callback window follows → instance = take … next rcl_wait entry) is implemented for applications that process the message inline; it did not trigger in this app nor in Autoware (0 such subscriptions; the only takes outside callbacks are polled reads and rmw's discovery thread). Daemon fix on the way: a launch with no component container never became 'stable' (python/fish/gpu.py). The third stock example, time_triggered_wait_set_subscriber, busy-loops at ~14 kHz with or without FISH and floods a trace (14 GB in 12 min) — left out. |
