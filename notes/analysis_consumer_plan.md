# Analysis consumer for the full paper (item E1) — plan
Generated by Claude Fable 5.1 (Anthropic), 2026-10-03. Goal: show that the FISH model is *consumable* by an
existing analysis, and that the analysis' answer can be checked against the trace it came from.

## Chain
Occupancy/centerpoint are GPU and self-suspending (blocking waits) — too exotic for a first RTA. Take the
lidar preprocessing chain, single-threaded executors, DDS + intra-process hops, periodic source:
  rosbag /sensing/lidar/*/pointcloud_raw_ex (10 Hz) → crop_box → distortion_corrector → ring_outlier →
  concatenate_data (join, 2+ inputs) → [crop_box_filter_measurement_range → voxel_grid_downsample →
  random_downsample] (localization util) — all CPU, all measured (ipc_fifo / rmw_take) in fish_20261003_104424.

## Task set from the model (what the extractor already has)
- per callback F: period (timer) or triggering edge, WCET/ACET from the sched_switch split (on-CPU time
  only, not window length), executor (EX vertex: ST/MT, thread count, cb groups), node.
- per edge: kind (sub / join / polled-msg), hop p50/p90/max (ipc_fifo vs rmw_take).
- join semantics for concatenate_data: completer = the input that triggers, timeout timer as fallback.
Deliverable: `postprocess/export_taskset.py <session> --chain <topic...>` → JSON/YAML in the format of
ROS 2 analyses (e.g. the single-threaded executor model of Casini et al. 2019 / the Teper 2024 end-to-end
model): callbacks with (C, T or trigger, executor, chain membership).

## Analysis
- Casini et al. (ECRTS'19) response-time bound for callback chains on single-threaded executors (processing
  chains, reservation-based) — implementable in ~200 lines; needs per-executor callback sets + WCETs.
- Teper et al. (RTSS'24 / 2024) end-to-end latency (reaction time / data age) for the multi-threaded executor
  — if the chain crosses an MT executor (concatenate_data runs in pointcloud_container, MT 20 threads).
- Compare: analytical bound vs measured response time per callback (window length) and chain latency
  (publish→take hop sums + on-CPU) from the same session; report the gap and which model assumptions the
  trace violates (self-suspension in GPU callbacks, polled-msg edges, intra-process waitable dispatch).

## Why this is a paper result
- Closes the loop the WiP only promised: observed model → analysis → observed timing.
- Exposes the assumptions existing analyses make that the trace contradicts (precisely the FISH story).

## Steps / effort
1. export_taskset.py (1 day): chain selection by topic list, WCET from ksched split (needs kernel session →

2. rta_chain.py (1 day): Casini'19 bound for ST executors; MT executor per Teper'24 if needed.
3. Validation script (0.5 day): measured response times per callback / chain from gantt spans + hops.
4. Figure: bound vs measured per callback (one bar pair each) + chain latency CDF.
