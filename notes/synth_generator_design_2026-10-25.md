# Synthetic task-chain generator + validation loop — design (agreed with Fatih, 2026-10-25)
Generated by Claude Fable 5.1 (Anthropic). Supersedes the implementation plan of notes/synthetic_tests.txt (its
scenario framing S1–S6 and the reference-system primitives stay as the "realistic archetypes" layer).

## Goal
Applications whose behaviour we KNOW because we generated them: a ground truth that is independent of FISH, at the
instance level, from 2 callbacks to thousands, including the extreme shapes real systems do not offer (single chain,
deep chain, tree, star, complete bipartite fan-in, cycles, disconnected components) and the full mechanism zoo
(DDS / intra-process, composable containers, executor kinds, callback groups, rclcpp + rclpy, services, synchronizers,
custom joins, member state, GPU). The FISH graph forms around the generated callbacks; the verifier checks that every
edge FISH extracts is observed and exact, and that nothing is missing.

## Two layers, randomised separately
1. **Logical graph (callback level).** Vertex = callback with a role: timer source, subscription, service server /
   client, join (fusion), timer reader, sink. Edge = data dependency with a MECHANISM label: topic-DDS, topic-intra,
   service, member field (overwrite), member queue (copy, batch-clear), member deque sliding window (pop), member map
   keyed set + timeout (concatenate type), message_filters Exact / Approximate, pointer hold (shared_ptr kept),
   tf lookup. Generators: Erdős–Rényi, Barabási–Albert (hubs), layered DAG (pipeline), chain (depth up to 100+),
   in/out tree, star, complete bipartite (N→1 join), cycle (feedback loop broken by a timer reader or a rate limit),
   disconnected components. Size 2 … 10^3–10^4 callbacks.
2. **Deployment.** callback → node → process / composable container (component_container, _mt, _isolated), executor
   (SingleThreaded, StaticSingleThreaded, MultiThreaded-k), callback group (MutuallyExclusive / Reentrant), language
   (rclcpp / rclpy), QoS (reliability, depth), intra-process on/off per node, thread priorities, sim time vs wall.
   The same logical graph under different deployments is the main experiment: mechanism × deployment × language →
   did FISH observe the edge, with identity?

## Code per callback: two libraries
- **Compute profile:** calibrated busy loop (constant / uniform / bimodal / heavy-tailed), OpenMP region, CUDA kernel
  stub (grid, block, duration), H2D/D2H memcpy, stream choice (per callback / shared / several), sync vs async
  completion, small TensorRT-like fixed network, large vs small messages (600 kB cloud vs 24 B), sleep
  (self-suspension), shared mutex (lock contention), allocation pattern.
- **Data pattern** (consumption rule known → the oracle can write D(c)): field overwrite; queue copy + clear on publish
  (gyro_odometer); deque sliding window with pop_front; map keyed by input + timeout (concatenate_data); message_filters
  ExactTime / ApproximateTime; shared_ptr hold released on use; copy; conditional deposit; value-dependent consumption
  (time window). Patterns come from notes/state_links_truth_2026-10-05.tsv.
- **Realism:** distributions mined from real traces (Autoware callback durations, rates, fan-in degrees, message sizes,
  deposit/consume ratios) → "Autoware-like random graphs"; the six archetypes of synthetic_tests.txt as fixed topologies.

## Generation: code generation first, interpreter second (both from one descriptor)
- **Code generation (primary, Fatih's preference):** jinja2 → real rclcpp / rclpy packages per seed (one package per
  seed in one workspace, `colcon build --parallel-workers N` + ccache; memory, not CPU, limits the parallelism). Real
  source → the static class analysis and the "looks like a real node" property are exercised; compiled against the
  overlay headers (fishwait27-based synth image) so the template hooks fire.
- **Interpreter (secondary):** one generic `fish_synth_node` binary (component-loadable, rclpy twin) that builds its
  callbacks at start-up from the descriptor with the pattern library — thousands of callbacks without compiling, for
  the scale sweeps.

## Ground truth at the instance level: the lineage tracepoint
Every generated message carries a lineage tag (producing callback id, sequence number). Every callback instance emits
one event of a separate, tiny LTTng-UST provider, enabled only in synth sessions:
    synth:instance(cb, inst, in=[(cb, seq)...], out=[(cb, seq)...])
= "this run consumed these inputs and produced these outputs". Timer readers log the deposit they read; synchronizers
log the merged members; a message no instance lists as input was dropped. FISH never reads payloads (identity from
addresses, writer+timestamp, container ops, hooks), so FISH's instance pairs vs the lineage log is an honest test.
GPU: the app records which kernels (correlation ids) each instance launched → FISH's GPU attribution is checked too.

## Legality rules the generator enforces (+ a health run before any measurement)
at least one source (timer) per component; a cycle is broken by a timer reader or a rate limit (no message storm);
bounded QoS depths; a callback never publishes on a topic it subscribes to unless the scenario says so; no synchronous
service call inside a callback unless it is a deadlock scenario; Reentrant groups sharing state use a lock; caps on
processes (hundreds, not thousands) and containers; a warm-up window until all subscriptions match; total CPU demand
below the core count unless it is an overload scenario. Health run: no dead process, no unmatched subscription, QoS
drops within the expected bound.

## Verification loop
generate (seed, family, size, deployment) → build → run under FISH (synth image, tier max, probes + container shim) →
ingest → model → extract → verify → report; sweep seeds and knobs; every failure becomes a regression case; nightly.
Metrics: structure precision/recall per edge class and mechanism (FISH must not invent edges); instance-pair exactness
vs lineage (triggers, joins, sampled reads); join membership sets; drops; ages; timing (C vs injected duration, release
instants vs oracle timestamps); resource mapping (executor, thread, GPU stream); scaling curves (callbacks, rate,
processes) and per-tier overhead. Pass = no inferred edge in the task layer, structure P/R = 1, pairs = 1, ages within
tolerance. Results into PG (synth_runs) + a page.

## Where it lives
Generated code outside the FISH repo (fish_synth/ workspace, reproducible by seed); generator, templates, verifier and
sweep driver in the repo under tests/synth/ (layout of synthetic_tests.txt §4, extended).
