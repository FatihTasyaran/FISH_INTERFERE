# Node-internal data flow ("state links"): what the fishwait24 probes give — status 2026-10-05
Generated by Claude Fable 5.1 (Anthropic), 2026-10-05. Nothing committed.

## Question
An end-to-end chain (CARET Fig. 12) crosses nodes where one callback deposits and another callback of the same node
reads and publishes. The stored graph has these links by a structural rule only: every non-publishing subscription
callback of a node → every publishing callback of that node ("latest value is read"). Can the trace back them?

## Ground truth (source reading, 55 links of fish_20261004_024402, 25 nodes)
`notes/state_links_truth_2026-10-05.tsv` — per link: deposit code, storage pattern, member, reader code, verdict.
REAL 38, FALSE 17 (the rule over-approximates by 31 %). Patterns: field 23, queue 12, copy 10, ptr 9, none 1.
Two same-period timers of vehicle_cmd_gate were told apart from the trace (which one publishes
/control/current_gate_mode). vehicle_cmd_gate's true readers of kinematics / acceleration / steering are the
control_cmd subscription callbacks, which did not fire in the bag replay (no route → no trajectory).

Second session (fish_20261005_131046, final image without the tick hook, 1-2-3 only, 59 links): the same 3 links
observed by release (ndt 1,035 messages, ekf twist 558, ekf pose 179) — reproducible.
- 1: 23 subscription callbacks keep their message; 16 are overwritten by the next deposit, 7 are consumed by another
  callback. Observed consumers among the structural links: ndt_scan_matcher (pose buffer → cloud callback),
  ekf_localizer (twist queue → 20 ms timer, pose queue → timer). Outside the structural set the same event shows
  collector membership exactly: concatenate_data (which cloud was consumed by which completing callback),
  obstacle_pointcloud_based_validator.
- 2: 0 hits (22,563 publishes checked). Nothing in this replay publishes a retained message as it is.
- 3: under SIMULATED TIME a stamp is evidence only if it is not a /clock tick value. `now()` returns the last tick, so
  every message stamped with now() carries a tick and unrelated messages share it: of 120 published topics, 81 carry
  only tick values, 39 only measurement stamps, 1 both. The first rule ("equal in every output") produced a false
  positive in the second session (vehicle_cmd_gate mrm_state → status timer, 249/249, source says no link: two 10 Hz
  timers on the same ticks). With the tick rule: no structural link is confirmed by stamp in this replay; 66 of the 77
  cross-callback matches are tick-only; the non-tick ones are real lineage outside the structural set — gyro_odometer
  imu → twist callback (212/213 in 4 outputs), obstacle_pointcloud_based_validator (105/105). The image now stamps the
  /clock PUBLISHER (one event per tick; serialized publishes are read from the CDR buffer) so every session knows its
  tick values. In real time (no /clock) stamps are unique and the restriction disappears — not tested yet.
- A: nothing beyond the leading stamp (2,926 events; Control-type messages do not flow without a route).
- C: 102 application mutexes locked by 76 callbacks, 25 shared by ≥ 2 callbacks of one node; 447 call sites (about
  half rclcpp template code, a fifth node code, the rest plugin loading, message_filters, diagnostic_updater).
  Supports 2 structural links (ndt_scan_matcher, voxel_based_compare_map_filter). Its value is the blocking input:
  holder and waiters by callback. Clean run (fish_20261005_190415, 49.8 s window): 12.8 M acquisitions, 98 % of them
  from ONE call site (VoxelGridDynamicMapLoader, up to 74,628 per instance of the compare-map filter callback — the
  place where the shim's cost concentrates); 6 callback instances waited > 100 ms for that loader's mutex (up to
  0.79 s; the map-adding call holds it 0.80 s); longest critical section 13.4 s (NDT MapUpdateModule::update_map, one
  instance, nobody waiting); otherwise hold p90 5 ms, p99 22 ms, wait p99 7 µs.
- The dominant REAL pattern, `field` (17 links: a value copied or derived into a member), is invisible to all five.
- Side finding (model defect, already known): 1,816 messages are retained by subscription callbacks the graph does
  not have — the second subscription on one (node, topic): mission_planner / vehicle_cmd_gate kinematic_state
  (VehicleStopChecker), traffic_light_occlusion_predictor pointcloud_raw_ex.

## Bugs found on the way
- Lock shim v1 hung every node at start-up: `dlsym(RTLD_NEXT, "pthread_cond_wait")` returns glibc's OLD
  (GLIBC_2.2.5) function on x86-64; a wait through it is never woken. Fixed with dlvsym("GLIBC_2.3.2") + fallback;
  test_lock_shim.sh now has a notify-woken untimed wait. The first validation run had looked healthy by
  "no process died" — it had started no process at all: check started processes and trace size.
- Sessions: fish_20261005_121128 (empty, hung launch), fish_20261005_122352 (all on, image before the infra-topic
  skip; analysis filters them; has /clock tick values from the takes), fish_20261005_130314 (off),
  fish_20261005_131046 (1-2-3, image with the skip but before the tick hook → stamp matches cannot be qualified).
  The current fishwait24 (tick hook) has only been smoke-tested with a 9 s bag replay, not in a full Autoware run.

## Fork `fork-awintra1` (evening) — Autoware recompiled for the intra-process path; NOT part of the fishwaitNN line
Why a fork: rclcpp's intra-process delivery is template code, so its hooks only fire in binaries compiled against the
overlay headers. Image `autoware-dev-trt-a1000-fork-awintra1` = fishwait24 + `docker/overlay_patches/fork_awintra1.py`
(retention probe in SubscriptionIntraProcess::execute_impl) + 8 Autoware packages rebuilt into the overlay workspace by
`scripts/rebuild_header_tracepoint_users.sh` (pointcloud_preprocessor, compare_map_segmentation, ground_segmentation,
lidar_centerpoint, nebula_velodyne, probabilistic_occupancy_grid_map, occupancy_grid_map_outlier_filter,
detected_object_validation — the packages of the 26 nodes on intra-process edges; 5.5 min build).
Guards: label `fish.lineage=fork` + /root/trace_overlay_ws/FISH_FORK.txt; `run_overhead_modes.sh` refuses fork images
unless FISH_ALLOW_FORK=1 (and then writes FORK_IMAGE.txt into the campaign dir); `build_overlay.sh` refuses to build a
fishwaitNN tag on a fork base. Both refusals tested.
Consumer: `extract_fish_tasks.py` pairs an intra-process publish with its take by (process, message address) when
both events carry the address (prov `exact:message_address`), else the old order rule.
