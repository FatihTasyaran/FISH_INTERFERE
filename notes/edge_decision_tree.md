# FISH edge decision tree (callback layer, L3)
Generated by Claude Fable 5.1 (Anthropic), 2026-09-14. Source of truth:
postprocess/model_improved_pg.py — attribute_aspects, detect_joins, detect_state_links,
detect_polled_subs, add_horizontal_edges, measure_flows. Pipeline order matters:
joins are detected before state links, polled after inferred, edges emitted last.

Input: init events (what is wired) + execution events (what happened).
Every L3 edge is then lifted to E / N / EX by the union rule.

Q1  Do a publisher P (node X) and a subscription S (node Y) share a ROS topic T?    [init: rcl_publisher_init, rcl_subscription_init]
    (services ride hidden DDS request/reply topics rq/<srv>Request, rr/<srv>Reply that rcl never exposes as topics:
     0 publisher/subscription inits on them in the trace, so Q1 and Q2 are disjoint by construction)
    yes -> L2 msg edge P -> S. Then:
        Q1a which callback a of X published T?  [exec: fish_rclcpp_publish_link inside a's callback window]
             -> L3 msg edge a -> b for every main callback b of S (both delivery copies if S is intra-process capable)
             no publish_link in the session -> the L2 edge stays, no L3 measurement
        Q1b X == Y ? -> intra_node=True (kept: self-feedback is real)
        Q1c one side not traced (topic seen only as pub or only as sub) -> external=True, synthetic ext:T vertex
        measure: DDS  -> rmw_take paired to publish by source_timestamp  (flow_method=rmw_take)
                 IPC  -> consumer start paired to latest rcl_publish <= 50 ms (flow_method=ipc_time; only if rcl_publish fired)
                 none -> hop unmeasured (pure intra-process: no rcl_publish and no rmw_take; idle topics)
    no  -> Q2

Q2  Do a client C (node X) and a service server V (node Y) share a service?          [init: rcl_client_init, rcl_service_init]
    (exec: fish_rclcpp_client_request_sent / client_response_received / client_link on the client,
     callback_start/end of the service callback on the server; stock rmw_send_request/take_request/
     send_response/take_response exist but FISH does not enable them.
     An action = 3 services (send_goal, cancel_goal, get_result) here + feedback/status topics in Q1;
     detect_actions tags both with action_name/action_role.)
    yes -> L3 dep edges: request  C(main) -> V(main)
                         response V(main) -> C(continuation F split by client_link / response_received;
                                             fallback: C main if no client_link was captured)
    no  -> Q3

Q3  In one node Y, is a DATA topic T published from >= 2 DIFFERENT subscription callbacks?   [exec: publish_link; infra topics excluded]
    yes -> join group T:  completers = those subs
                          members    = Y's other subs on data topics with the same msg_type as a completer
                          timeout    = Y's timers that also published T
          -> L3 join tie edges member -> anchor completer (membership, NOT a hop; no data edge invented)
    no  -> Q4

Q4  Was a message of subscription S pulled by application code rather than dispatched?   [exec: rmw_take (per_instance), callback_start/end]
    A message reaches S's process in two ways only:
      (a) executor dispatch: the executor thread waits, calls take() BETWEEN callbacks, then starts S's own
          callback c_S within microseconds -> the rmw_take lies outside every callback window;
      (b) application pull: code running inside some other callback r (a timer, another subscription's
          callback, a service handler) calls Subscription::take() itself -> the rmw_take lies INSIDE r's window.
    Test, per rmw_take event with taken = 1 on S's rmw_subscription_handle, at time t on thread tau:
      r := the innermost callback whose callback_start <= t <= callback_end on the same thread tau
      r exists  AND  r is not c_S  AND  S's topic is a data topic
    yes -> polled-msg (observed; paper name) S -> r; n_polls = number of such takes; age = t - source_timestamp of the taken message
          (Autoware's InterProcessPollingSubscriber creates S in a callback group that is never added to an
           executor, so c_S never fires at all; mark_phases keeps S in the data phase.)
    Not counted: takes outside every window (case a); takes inside c_S itself (re-entrant take of one's own
    subscription, e.g. draining a queue); takes on infra topics.
    no  -> Q5

Q5  In node Y: S is a data-topic subscription whose callback fired >= 1 time, whose entity publishes NO data topic,
    and which is not a join member;  P = callbacks of Y whose entity publishes >= 1 data topic (timer/sub/service/client)
    yes -> state-inferred (assumed; NOT in the paper, optional tool overlay) S -> p for EVERY p in P; age = start(p) - last start(S) before it
    no  -> no edge

Not edges (known blind spots): tf2 buffer reads (/tf is infra), cuda_blackboard payloads (only the key
travels as a msg), loaned-message takes (no tracepoint), intra-process hops (edge exists, hop unmeasured).

Precedence when several apply to the same pair: join membership removes S from Q5; a polled S never fires,
so it never enters Q5; if an (S, p) pair is both inferred and polled, the emitted edge is polled (observed wins).
