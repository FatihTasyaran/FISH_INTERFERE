# What FISH adds over ros2_tracing + nsys (draft table for the full paper)
Generated by Claude Fable 5.1 (Anthropic), 2026-10-03. Facts from notes/tracepoint_coverage.md and the model code.
Answers reviewer 12C ("how much is new vs. a configuration of existing tools").

| capability | ros2_tracing (Humble) + nsys | FISH |
|---|---|---|
| callbacks dispatched by the executor | timer, subscription, service | + client responses, waitables (intra-process deliveries, action servers): 2 of the 5 kinds were invisible |
| which executor runs a callback, callback groups, MT thread count | not recorded | executor_init / add_cbgroup / callback_group_init / cbgroup_add (4 TPs) |
| which callback published a message | not recorded (rclcpp_publish has no callback) | publish_link (also for intra-process-only publishers, via a compiled hook that stock-built binaries reach) |
| intra-process delivery | no events in Humble | waitable dispatch windows; per-message intra_publish (fishwait12) |
| serialized / loaned takes (GenericSubscription, zero-copy) | no tracepoint anywhere | fish_rcl_take (fishwait12) |
| GenericSubscription dispatch (create_generic_subscription: topic_state_monitor, pipeline_latency_monitor, topic_tools relays, rosbag2 record) | no registration, no callback_start/end — the callback never appears | registration (hpp hook) + callback_start/end (fishwait13, compiled) |
| tf buffer reads (/tf → tf2 buffer → lookupTransform in another callback) | nothing after the /tf subscription callback; the consumer is invisible | fish_tf_set_link + fish_tf_lookup in libtf2.so (fishwait14): reader callback, frames, requested vs resolved stamp → polled-msg edge |
| object lifetime (handle reuse) | init only | *_fini for node, pub, sub, service, client, timer |
| rclpy | no tracepoints | ctypes shim: registrations, callback_start/end, client req/resp, publish_link |
| GPU work → callback | nsys: → OS thread only | thread's active callback at submission → callback; typed DAG per invocation; shapes; conditional graph |
| OS scheduling of callbacks | not correlated | sched_switch ∩ callback windows: on-core / preempted / blocked; sched_waking → helper threads (assist) |
| edges beyond pub/sub and services | none | join (publish from ≥2 input callbacks, message_filters symbol), polled-msg (take inside another callback) |
| acquisition | user runs lttng + nsys by hand, GPU processes must be started under nsys | launch wrapping (plugin/package heuristic + /proc/maps safety net), system-stable signal, phases from the trace, shutdown-time provenance snapshot |
| model | per-message trace | containment hierarchy H/EX/N/E/F with lifting; expansion operator; viewer |
| validation | — | ros2 node info vs model: recall 1.000 on all interface kinds (Autoware, 225 nodes) |
