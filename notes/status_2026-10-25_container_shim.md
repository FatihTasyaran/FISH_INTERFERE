## Why interposition works (checked on libautoware_gyro_odometer.so)
push_back / clear are inlined, but libstdc++ keeps the slow paths out of line as weak, default-visibility symbols:
`deque<T>::_M_push_back_aux` (libstdc++ chunk = 512/sizeof(T) elements, so for sizeof(T) > 256 B one element per
chunk and EVERY push goes through the slow path — Imu 336 B, TwistWithCovarianceStamped 376 B; small messages only
every n-th push), `deque<T>::_M_erase_at_end` (clear). The
component library calls them through the PLT (R_X86_64_JUMP_SLOT relocations), so an LD_PRELOAD library that defines
the same mangled symbol is called first and forwards with dlsym(RTLD_NEXT). A standalone executable binds its own
instantiations directly — the regression test therefore puts the node logic in a shared library.

## First validation run: 9 processes aborted (fish_20261025_133112, overhead_aw_20261025_143106 — discarded)
The shim resolved the real function with dlsym(RTLD_NEXT). ROS 2 component libraries are dlopen-ed RTLD_LOCAL by the
class loader, so their instantiations are invisible to RTLD_NEXT: the hook found nothing and aborted (policy copied
from the lock shim) — 3 pointcloud containers, behavior_planning, gyro_odometer, 2 traffic-light nodes died at the
first push. A second defect in the filter: `map<string, shared_ptr<rclcpp::Publisher<Msg>>>` (publishers keyed by
topic) matched `::msg::` and was interposed although it is not message flow.
Fix (gen_container_shim.py): the trampoline passes the return address; the hook resolves in the CALLER's object first
(dladdr → dlopen(RTLD_NOLOAD) → dlsym), then in every loaded object (dl_iterate_phdr), then RTLD_NEXT; the filter
drops anything containing `rclcpp::` → 58 symbols (50 deque, 8 map/umap), 40 libraries. The regression test now loads
the test node as a plugin (dlopen RTLD_LOCAL) and passed; the real gyro_odometer node and a component container
loading a pointcloud_preprocessor plugin ran with the shim without an abort. fishwait27 rebuilt with the fix.

## Evidence semantics (what each label means)
- container:observed — push into a std::deque member in instance u, erase/clear of that container in instance v:
  v absorbed the deposit (used, or cleared on an error path: gyro's timeout branches clear without publishing).
- exact:message_filters — synchronizer hooks: the merge inside v names its member deposits (stamps).
- pointer:held@publish — u kept a reference (retain), v is the first callback of the node that PUBLISHED while the
  message was still held; the release instant alone is NOT consumption (concatenate releases the previous cycle in
  the next cycle's first callback).
- pointer:release — the last reference went in v without any publish during the hold: a drop, reported, never an edge.
- timer readers get these pairs as sampled dependencies (exact ages), not as task membership: the timer's activation is
  its period, not the deposit.
