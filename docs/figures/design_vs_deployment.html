FISH · design vs deployment · numbers from r25 (fish_20260824_154257) and r11

Five behaviours: what the source says, what happens at deployment, how FISH models it

The FISH model always favours deployment: the constructed model translates the design into what actually happened. Each row reads left to right — the structure the source code implies, the structure the trace shows, and the vertices, edges and attributes FISH keeps for it.

1 · Join — concatenate_data: three symmetric callbacks, one completer

Design (source)

Every lidar callback carries the same body: "if all three are here, concatenate and publish". The design is symmetric; which one completes is undecided.

Deployment (trace)

Top arrives last, so top completes; right only fills the buffer. When a lidar is missing, the 200 ms timeout timer publishes the partial cloud.

FISH model

detect_joins groups the F vertices that publish the same output topic; the role comes from the trace: completer {top, left}, member {right}, 3 timeout timers.

  • edge: nature=join · flow_n · hop_ns_p50 · tau

2 · Polled subscription / take(): designed as callbacks, executed as reads

Design (source)

InterProcessPollingSubscriber: the source has a subscription and an (empty) callback per input. Without the reading code you would assume "every message triggers a callback". 249 uses in Autoware.

Deployment (trace)

One trigger, the timer; the inputs are read with rmw_take inside another callback's window (sample-and-hold). The "subscription triggers" chain of the design does not exist.

FISH model

detect_polled_subs: an rmw_take(taken=1) inside another callback's window becomes a polled state edge from the source F to the reading F; age = take − source timestamp. The trigger chain runs through the timer; the inputs are drawn as grey "deliver" hops in the FT view.

  • edge: nature=state · polled=True · inferred=False · age_ns_p50
  • no rmw_take seen → inferred=True state link
  • r25: 71 polled_take edges, 60 inferred

3 · Waitable — one subscription, two dispatches

Design (source)

The code says one thing: subscribe to this topic, call cb when a message arrives.

Deployment (trace)

With intra-process communication on, rclcpp creates a second entity; the executor handles every message first as the Waitable wrapper, then as the inner callback. r25: 143 waitables, 9464 = 9464 dispatches.

FISH model

The E count is not inflated: the sub E gets ipc_waitable and delivery, the wrapper dispatch folds into the inner F. Other Waitable kinds (action server/client, QoS events, rosbag2 player) become the fifth entity type with their own E and F.

  • from: fish_rclcpp_waitable_init(node_handle=0x0)
  • rclcpp_subscription_init ×2 (waitable, this)
  • rclcpp_subscription_callback_added → cb

4 · Timeout timer — designed to wait, deployed to give up

Design (source)

The intent: one merged cloud once all three arrive. The timeout is a side branch in the source.

Deployment (trace)

When a lidar is late the system does not wait: after 200 ms the timer publishes the partial cloud. In r25 this path produced 2780 downstream flows.

FISH model

The timeout is the third role of a join group: an F that publishes without completing. tau sits on the edge; which callback completed each period is visible in gantt-cb, where the timer and the top callback share a row.

  • edge: nature=join · tau=200 ms · flow_n=2780

5 · Executor — sequential per node in the design, interleaved in a container at deployment

Design (namespace tree)

Architecture drawings are namespace trees; where a node's callbacks run, and with whom, is not part of the design.

Deployment (r11, ps + trace)

One process, one MultiThreadedExecutor, four namespaces. Callbacks interleave on 20 shared threads; "namespace = resource owner" breaks (ε = 26 s, 6.11 %).

FISH model

EX is its own vertex: process, executor type, thread count, callback groups. The namespace layer is orthogonal to EX; ε is the EX time that belongs to no namespace. The thread and callback gantts show the interleaving.

  • gantt-tid: by thread · gantt-cb: by callback · cb-stats
  • F.callback_group → MutuallyExclusive | Reentrant
  • F6: EX→ns without copies — ε vs ⧉ (design_abstraction_axes.txt)
